GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業は自分のマシンでリアルタイムに実行されるため、VS Code の Copilot Chat ではツールの呼び出しやファイルの編集を確認できます。差分をインラインでレビューし、個々の変更を採用または却下できます。また、エディターを離れずに追加プロンプトを送って会話を導き、作業を改善したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに指示し、高コントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加したいとのことです。新たに会話を始める代わりに、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行するコマンド、提案する編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると変更が適用されます。
   - **Undo** を選択すると変更が元に戻り、エージェントは改めて修正を試みます。
4. チャット上部の **Files changed** を開いて、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツール呼び出しの許可を求められた場合 (たとえば、ターミナルコマンドの実行)、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

高コントラストモードを追加できたので、同じ会話でライトモードの切り替えも実装します。同じチャットセッションを続けることで、エージェントは変更したコンポーネント、採用したスタイル、設定した local storage のパターンなど、以前の作業コンテキストを保ちます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは以前の作業から再開し、既存の変更を調査してライトモードの追加を提案します。
3. 高コントラストの場合と同様に、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントが期待と異なる方向に進んだ場合 (たとえば、好みと異なる方法でトグル UI をリファクタリングしようとする場合)、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加プロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を追加するほうが、最初からやり直すよりも速く済みます。追加プロンプトで修正を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」など)、方向を調整できます (「トグルを 3 つに増やさず、既存の設定パネルにライトモードを追加する」など)、範囲を広げることもできます (「両方のトグルにキーボードショートカットも追加する」など)。

## 作業ファイル全体をレビューする

作業をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。たとえば ARIA 属性、キーボード操作、セマンティック HTML、local storage による永続化です。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して指示しました。ファイルの編集ごとにレビューし、変更を採用または却下し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

この演習では、次のことを確認しました。

- エージェントの作業をリアルタイムに監視する方法。
- 個々のファイル編集を採用または却下する方法。
- 進行中のセッションに追加プロンプトを送り、作業を導く方法。
